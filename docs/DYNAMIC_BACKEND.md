# 动态类型后端设计

## 当前支持情况

编译器使用 `src/ir.zig` 的固定布局 Zig 后端，尚不支持运行时类型执行。

目前支持编译期类型值重绑定、结构声明展开、增量扩展、默认值声明保留、Self 版本化及 HAMT 成员索引。运行时条件中的类型赋值仍会报错。

固定布局后端已支持 Heap、Arena、ARC 和追踪 GC，编译器会生成托管指针的复制、清理和根登记。下面关于内存和生命周期的设计指运行时类型描述符、动态对象及其环境。 [已实现的内存接口](LANGUAGE.md#内存分配与清理)

## 结构扩展的词法环境与类型身份

- 继承的声明保留原词法父环境，新声明使用扩展位置的环境。因此，已有 `[n]i32`、默认值和方法中的名称不会因扩展位置存在同名常量而改变含义。
- 默认初始化的排除字段变体也使用声明原环境，而不是最终结构或调用位置的环境。
- 方法的成员查询通过所属结构作用域进行，词法父环境单独保留，避免切换结构版本时改变外部常量的含义。
- 旧式成员赋值产生新版本时，签名按 AST 中的 `Self` 位置递归更新数组、切片、指针和函数类型；已解析的显式类型别名及数组长度保持不变。不是将所有“恰好等于旧类型”的类型替换成新类型。
- 只有赋值 RHS 本身是结构表达式时才向它传入展开目标；函数调用、调用参数和嵌套结构不能借用该目标。
- HAMT 成员索引支持持久化更新，已有快照不随新版本改变。测试通过可注入哈希函数覆盖完整哈希碰撞、最后四位分叉、碰撞桶拆分、同键更新和缺失键。
- 扩展导入类型后，其默认值不能捕获新实例祖先链之外的容器运行时字段。这类跨容器捕获尚未实现，会报 `structure cannot capture runtime member ... from an unrelated container`。可解析的整数编译期常量不需要该运行时环境。

`examples/basics/struct_extension_scopes.saph` 展示词法环境、默认初始化变体、显式旧别名和 `Self` 区分；`examples/basics/struct_extension.saph` 展示旧实例和结构扩展。

## 为什么不能只替换 Layout 或取消静态诊断

当前 `semantic.Value.type_value` 是编译器内存中的 Type，`runtimeExpr` 拒绝生成它的运行时代码；`invoke` 从运行时参数中删除 type 参数。`ir.Type.structure` 和 `pointer` 仅保存一个静态布局编号，`Expr.object.shape` 也是静态编号；所有字段访问、数组元素布局和函数 ABI 已据此确定。

若仅允许运行时分支修改 Analyzer 中的绑定，会在编译阶段依源码分析顺序改变类型，而不是在程序运行时依实际分支改变类型。若仅将对象替换为指针，则会破坏当前结构及数组的值复制、切片共享、显式借用和绑定方法接收者语义。用户实验文件的简单 Value/Kind 也没有覆盖本语言的全部数值位宽、嵌套结构、数组、枚举、方法签名和默认初始化环境，不能直接代替现有 IR。

## 必需的 IR 与语义变更（设计，尚未实现）

| 位置 | 必须增加或改变的表示与操作 |
| --- | --- |
| 类型值 | 新增可在运行时传递的 `TypeRef`/descriptor 值；原始类型、结构、指针、数组、切片、函数和枚举均需要类型描述。不能用 Zig 的编译期 `type` 作为运行时值。 |
| 类型绑定 | type 局部和字段需要真正的 IR slot；赋值生成运行时 store，条件分支和循环沿正常控制流执行，不能修改全局 Analyzer 绑定代替执行。 |
| 结构构造和扩展 | 新增 `shape_create` / `shape_extend` 操作，输入旧 TypeRef 和声明模板；HAMT 持久化更新并检查重复成员，成功后发布新 TypeRef，旧描述符永不修改。 |
| 对象 | `object_new` 输入运行时 TypeRef；对象保存构造时的 descriptor 快照及值存储。复制对象必须复制其值而不是仅复制一个可变对象指针；旧实例不得回查可变类型绑定。 |
| 字段和左值 | 新增带 descriptor 检查的字段读取、写入及投影左值；写入按字段原类型检查。嵌套字段、数组元素、use 路径和可变借用必须共享同一套投影规则。 |
| 数组、切片、枚举 | 元素或 payload 含动态结构时，不能继续使用固定 Zig `[N]S{id}`；需 descriptor 驱动的元素大小、复制、索引、payload 表示和一致性检查。切片仍须共享底层存储。 |
| 默认初始化 | 声明模板保存 initializer thunk 及明确的词法环境；按顺序执行，显式给出的字段跳过默认值。不同来源声明可能需要多份环境，不能仅靠一个 `__module_context` 指针解释全部默认值。 |
| 方法和 Self | 保留方法模板与 Self 类型表达式；在实际完整 descriptor 上实例化签名。应采用可操作动态 Value 的已编译模板/解释 IR，或明确的运行时特化机制；不能假定运行时可以重新调用 Zig 编译器。显式旧别名仍保存旧 TypeRef。 |
| 调用 ABI | 增加动态调用入口、类型参数和返回 TypeRef 的实际传递，以及参数/返回类型检查；绑定方法同时保存接收者身份、实例 shape 和词法环境。旧 direct/indirect 静态调用路径不能无条件复用。 |
| 控制流类型检查 | 类型绑定有运行时多种可能值时，构造与成员访问需要明确的静态保证或运行时错误；不能任选编译期分析到的一个布局。错误需要源位置和一致的失败策略。 |
| 内存和生命周期 | 描述符、HAMT、实例值、初始化环境需要所有权和回收策略。必须保持值复制与指针/切片语义，防止副本别名和悬垂环境。进程级 Arena 只能是明示限制的原型方案。 |

## 安全迁移顺序

1. 先确定 descriptor、动态值复制、投影借用和错误 ABI，给运行库独立测试，包括完整语言值种类和内存清理。
2. 新增动态 IR 节点与验证器，在独立后端中覆盖构造、默认值、字段读写和旧实例快照；保留现有固定布局生成器。
3. 贯通运行时 type slot、分支、循环、参数和返回值，之后接入方法模板与 Self、use 和跨容器环境。
4. 两条后端运行相同的值语义回归，并增加真正依赖运行时条件的类型修改用例。动态路径完整支持这些语义后再将其设为默认；固定布局路径可暂时不可选，或仅作为优化实现保留。
